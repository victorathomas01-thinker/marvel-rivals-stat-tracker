# Marvel Rivals Stat Tracker

[Release instructions](RELEASE.md)

A Chrome extension that turns visited Tracker.gg match pages into personal matchup history and observed loss rates.

**[Two-minute walkthrough](DEMO.md) · [Install the extension](#install-locally) · [Data and exports](#data-model)**

| View | What it answers |
| --- | --- |
| Observed loss rates | How often did I lose when this hero appeared, with sample counts and 95% intervals? |
| Recently recorded matches | Which matches did the extension capture most recently? |
| Offline demo | Can I reproduce the displayed rates from an exported history? |
| Weighted loss totals | Which heroes contributed most to the original weighted-loss summary? |

**Try it.** Download this branch, open `demo.html`, and inspect the synthetic matchup view. Open a version 1 history export with the file picker to recompute its results locally. Follow the install steps below to capture visited match pages.

**Engineering evidence.** Six unit tests and Chromium integration checks passed before this documentation update. Anonymized fixtures cover historical scoreboards and current supplied win/loss captures, including Team B appearing first and a player name without a profile link.

**Measured behavior.** With 10,000 synthetic records in a temporary local Chromium profile, median storage reads measured 440 ms for all records and 2.5 ms for a keyed duplicate lookup. Popup readiness measured about 305 ms. The popup still reads history to compute analytics.

**Interpretation.** Rates describe the matches you visited. Hero combinations, maps, opponents, and sample selection affect them. The popup displays heroes after five encounters.

## What It Does

The extension reads individual Tracker.gg match pages, determines which team the configured player is on, checks the final score, and records opposing heroes on wins and losses. Draws are stored for deduplication.

Enemy heroes associated with an MVP or SVP row receive a **1.2× weighted-loss value**, making standout performances count slightly more heavily in the threat ranking.

## Features

- Detects the configured player on Team A or Team B
- Reads match scores directly from the Tracker.gg match header
- Records opponent heroes on wins and losses
- Supports multiple hero images for players who switched heroes during a match
- Applies 1.2× weighting to MVP/SVP opponent rows
- Deduplicates previously processed match IDs
- Stores data with the Chrome Storage API
- Displays a Top 5 Threats overlay directly on match pages
- Provides a browser-extension popup with the same threat summary
- Lets the user configure their Tracker.gg player name
- Exports tracked data as JSON or CSV
- Provides a clear-data control

## How It Works

1. Wait for Tracker.gg match data to render.
2. Locate the Team A and Team B stat tables.
3. Find the configured player name and determine that player's team.
4. Read Team A and Team B scores from the match header.
5. Inspect the opponent rows.
6. Extract hero names from hero-image metadata while ignoring non-hero images such as rank icons.
7. Detect MVP/SVP labels and apply the 1.2× weight where appropriate.
8. Save one record per player and match ID through the extension service worker.
9. Show weighted loss totals and observed loss rates in the popup.

## Data Model

The weighted loss view and its aggregate exports use this shape:

```json
{
  "losses": 3,
  "appearances": 3,
  "weightedLosses": 3.2,
  "mvpSvpAppearances": 1
}
```

The threat list is sorted primarily by `weightedLosses`, then raw losses and appearances.

## Two-minute walkthrough

1. Open `demo.html` to see synthetic results and recent matches.
2. Pick a hero and explain the encounter count and 95% interval.
3. In the extension, export a match history and open it from the demo's file picker to reproduce the recent list and matchup rates.
4. To build the installable bundle, run `python scripts/package_extension.py dist/marvel-rivals-stat-tracker.zip`. Extract the ZIP and use the folder containing `manifest.json` in the steps below.

## Install Locally

1. Download or clone this repository.
2. Open `chrome://extensions` in Chrome.
3. Enable **Developer mode**.
4. Choose **Load unpacked**.
5. Select the repository folder.
6. Open the extension popup and confirm your Tracker.gg player name.
7. Visit a Marvel Rivals match-detail page on Tracker.gg.

### Observed loss rates

Each hero counts at most once per match in the rate view. After five encounters, the popup shows losses divided by recorded wins plus losses and a 95% Wilson interval. It ranks heroes by the lower bound of that interval. These are descriptive rates from visited matches. Maps and co-occurring heroes can affect the result.

New records are scoped to the configured player and retained until you clear tracked data or remove the extension. Earlier versions stored only totals and up to 500 recent IDs. Those totals are available separately as unassigned legacy data and known IDs are skipped. The rate view uses new records. Matches whose IDs had already expired in the earlier version can overlap with legacy totals if revisited.

## Match-history export

**Export Match History** downloads versioned JSON for the selected player. It contains match IDs, outcomes, scores when available, and opponent hero appearances. It omits the configured player label. Match IDs can still connect records to match pages. The timestamp is when the extension recorded the match. The export uses null for timestamps and scores that were unavailable in older records. Earlier aggregate-only data remains available through the summary exports.

The popup also shows the five most recently recorded matches for the selected player. The offline demo can open an exported JSON file locally and runs the same encounter calculations as the popup. Imported exports remain in the demo tab's memory.

The popup shows observed loss rates first. Expand **Weighted loss totals** to see the historical scoring view and use the summary export buttons for its CSV or JSON.

## Validation

Run `node --test tests/tracker.test.cjs` to check player lookup, duplicate writes, and encounter-rate math.

The current parser was checked against saved Tracker.gg match-page fixtures representing both a loss and a win. In the loss fixture, the parser correctly isolated the opposing team and detected the MVP-weighted hero row. In the win fixture, it correctly skipped loss-stat updates.

The saved fixture pages are not included in the public repository because they contain third-party page markup and player/match data.


The Chromium integration test loads the unpacked extension against a synthetic scoreboard fixture. It covers wins, losses, draws, deduplication, and the downloadable history. Install Playwright with `python -m pip install playwright==1.64.1`, then install Chromium with `python -m playwright install chromium` and run `python -B -m unittest discover -s tests -p test_extension.py`. The suite also uses two anonymized fixture layouts reconstructed from saved March 2025 Tracker.gg scoreboards. They retain the score and team structure, use substitute names and hero labels, and remove original links and unrelated page content. Two more anonymized layouts cover a current win and loss captured from rendered Tracker.gg scoreboards in November 2026. In both, Team B appears first and the tracked player has a visible name without a profile link. The suite checks the score, selected team, opponent hero counts, revisit deduplication, and export. These fixture checks assess the captured page layouts.
## Engineering Decisions

### Narrow host permissions

The extension only runs on Tracker.gg Marvel Rivals match-detail URLs instead of requesting access to all websites.

### Match deduplication

Processed match IDs are stored so refreshing or revisiting the same page does not repeatedly inflate the statistics.

### Hero-image filtering

Tracker.gg rows contain both hero images and rank images. The parser filters image URLs for the hero asset path before reading the image `alt` text.

### Configurable player name

The original prototype was built around one account. The public version makes the player name configurable so the extension is reusable without editing source code.

## Current Limitations

- The project depends on Tracker.gg's current DOM structure and may require selector updates if the site changes.
- It processes individual match-detail pages as they are visited; automated traversal of an entire match history is not implemented yet.
- Automated browser tests are not yet included.

## Background

I built this project because the standard match-history view made it difficult to answer a practical competitive question: **Which enemy heroes repeatedly show up in my losses?**

The project became an exercise in DOM inspection, data extraction, defensive parsing, state persistence, browser-extension design, and turning raw match data into a small decision-support tool.
